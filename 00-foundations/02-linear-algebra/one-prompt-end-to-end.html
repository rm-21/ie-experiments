Prefill and arithmetic intensity are two different kinds of idea. Prefill is a phase: the first pass, where all prompt tokens go in. Arithmetic intensity is a score you can give any matmul: FLOPs per byte moved. Prefill gets a high score because it puts many rows into each matmul.

The two ideas, side by side

Idea Kind of thing Question it answers Unit
Prefill / decode a phase of generation Which tokens go into this pass? tokens per pass
Arithmetic intensity a property of one matmul How much math do I get per byte I fetch? FLOPs / byte
Rows (M) the link between them How many tokens share one weight fetch? rows
How they connect

The phase decides M. M decides the intensity. Prefill has a big M, so its intensity is high. Decode has M = 1, so its intensity is about 1.

Step 2: each ID becomes a row of 2048 numbers

The model has a table with one row per vocabulary entry. It looks up each ID and copies out that row. The result is x, a matrix of shape 6 × 2048.

Row Token The row: 2048 numbers
0 <|begin_of_text|> [ … 2048 numbers … ]
1 The [ … 2048 numbers … ]
2 capital [-0.0327, 0.0327, 0.0245, 0.0573, … 2044 more]
3 of [ … 2048 numbers … ]
4 France [ … 2048 numbers … ]
5 is [ … 2048 numbers … ]
  • A row is one token. Your prompt sets the number of rows: 6 here, 234 for your long prompt.
  • 2048 is the width of every row. The model sets it. It never changes, because the weights are 2048 × 2048.
  • The numbers for capital are its real first 4 values.
D

Step 3: what a layer does

A layer is a few weight matrices. Each one does the same thing: rows @ W. That is the matmul from la.py.

A tiny example you can check by hand. Pretend the width is 3, not 2048, and there are 2 tokens.

x (2 rows × 3) @ W (3 × 3) = new rows (2 × 3)
France [1, 0, 2] [1, 2, 0] [3, 2, 2]
is [0, 1, 1] [0, 1, 1] [1, 1, 2]
[1, 0, 1]
  • Each token's row goes in. A new row for the same token comes out.
  • First number for France: 1·1 + 0·0 + 2·1 = 3.
  • W is the same for both rows. The chip fetches it once and uses it for every row.

A real layer does this 7 times, with bigger W matrices:

Matmul Rows in W Rows out
4 for attention 6 2048 × 2048 (or × 512) 6
3 for the MLP 6 2048 × 8192 (or 8192 × 2048) 6
  • Rows in = rows out. 6 tokens go in, 6 come out, at every step.
  • One small extra step (attention) lets rows look at each other. That is how is learns it is about France. Later phases cover it.
  • 16 layers × 7 matrices = 112 weight fetches per pass. Keep this number. Panel H uses it.

Where prefill and decode fit

Prefill and decode are only names for passes.

Pass Name Rows in (M) Why that many rows
1 prefill 6 You wrote the whole prompt already, so all its tokens go in together.
2 decode 1 Paris did not exist until pass 1 finished.
3 decode 1 . did not exist until pass 2 finished.
… decode 1 Each token waits for the one before it.

Prefill is a phase with many rows. Decode is a phase with one row. Nothing else changes: same model, same 16 layers, same weights.

Where arithmetic intensity fits

Now score one matmul inside each pass: x @ W_q, with W_q = 2048 × 2048 at 2 bytes per number.

Pass M FLOPs (2·M·2048·2048) Bytes (x + W_q + y) Intensity
1 (prefill) 6 50.3 M 8.44 M 6.0 FLOPs/byte
2 (decode) 1 8.4 M 8.40 M 1.0 FLOPs/byte
your long prompt (prefill) 234 1.96 G 10.31 M 190 FLOPs/byte
  • W_q costs 8.39 MB in every pass, for any M.
  • More rows means more math on the same fetched weights.
  • A full pass repeats this for all 112 weight matrices from panel D. Prefill shares each fetch across all prompt rows. Decode uses each fetch for 1 row.
  • So intensity is not a phase. It is a measurement. Prefill scores high because it brings many rows.
Simplification

The table uses 2 bytes per weight so the numbers stay simple. Your model stores weights in 4 bits, so the real W_q is about 4 times smaller. The pattern is the same.

The whole chain in one line

  • Phase decides how many tokens are ready to go in.
  • M is that number of rows.
  • Intensity is FLOPs per byte for a matmul with M rows.
  • Speed follows from intensity. This is why your prefill ran at 2034 tok/s and decode at 257 tok/s.
