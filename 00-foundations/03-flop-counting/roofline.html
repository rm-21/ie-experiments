Roofline, explained with two workers

Phase 00 · Lesson 03 (FLOP counting) · No formulas until they've earned their place.

1Two workers, one job

Your chip has two workers who work at the same time:

🧮 Calculator
Does the math.
Speed P = FLOPs per second
Real name: compute units (GPU cores, tensor cores, CPU SIMD units). Their speed is peak compute throughput, in FLOP/s.
🚚 Carrier
Brings numbers in from memory.
Speed B = bytes per second
Real name: the memory system (DRAM/HBM to the chip). Its speed is memory bandwidth, in bytes/s (GB/s).
The job is done when both are finished. You always wait for the slower one.

2A toy machine

Calculator: 10 FLOPs/sec. Carrier: 2 bytes/sec.

Job A: 20 FLOPs, 8 bytes
🧮 Calculator20 ÷ 10 = 2 s
🚚 Carrier8 ÷ 2 = 4 s
Takes 4 s. memory-bound
Job B: 100 FLOPs, 8 bytes
🧮 Calculator100 ÷ 10 = 10 s
🚚 Carrier8 ÷ 2 = 4 s
Takes 10 s. compute-bound

Job B is Job A with more math reusing the same bytes, like more rows going through the same weights.

3Why Job A is "slow": the calculator starves

Job A has 2.5 FLOPs of work per byte. Watch it second by second:

122 × 2.5 = 5105 then idle

425105 then idle
The job isn't too demanding. It's too light on math. Data arrives at 2 bytes/s × 2.5 FLOPs per byte = 5 FLOP/s, so the calculator runs at half its speed and waits for data the rest of the time.

Job B, by contrast: 2 bytes/s × 12.5 FLOPs per byte = 25 FLOPs of work arriving each second. The calculator can only clear 10, so work piles up and the carrier ends up waiting.

🍳 A chef who can cook 10 dishes/hour, with ingredients arriving for only 5 dishes/hour, isn't slow. They're waiting for ingredients.

4One question instead of two divisions

Intensity = FLOPs ÷ bytes
The work this job gives per byte.
Job A: 2.5 · Job B: 12.5
Ridge = P ÷ B = 10 ÷ 2 = 5
The work per byte the calculator needs to stay busy.
Intensity < ridgeThe calculator starvesmemory-bound
Intensity > ridgeThe calculator is swampedcompute-bound
Intensity = ridgeBoth busy all the timebalanced

The time formula you derived yourself: time = max(FLOPs ÷ P, bytes ÷ B).

The roof lineRoofline model (Williams et al., 2009)—
The roofline formulas
Arithmetic intensityI = F / Q
Ridge pointI* = P / B
Lower bound on timet ≥ max(F / P, Q / B)
Attainable performance (the roof)perf ≤ min(P, B × I)
Achieved FLOP/s (from a measurement)F / measured_seconds

The time form and the roof form say the same thing. Divide F by the time bound and you get the roof.

Where F and Q come from for a matmul (M, K) @ (K, N), with s bytes per element
WorkF = 2 · M · N · KK multiply-adds per output; 1 multiply-add = 2 FLOPs
TrafficQ = (M·K + K·N + M·N) · sRead A once, read B once, write the output once

Hand check: (2,4) @ (4,3) in fp32 (s = 4) → F = 2·2·3·4 = 48, Q = (8+12+6)·4 = 104, I ≈ 0.46.

Q is an idealized model of traffic, not a measurement. Caches, repeated loads and tiling change the real bytes moved.

Bytes per element (s): fp32 = 4 · fp16 / bf16 = 2 · int8 = 1 · 4-bit = 0.5

The line is the best possible speed at each intensity. Sloped part: the carrier limits you. Flat part: the calculator limits you. Real code lands below the roof, never above it.

7How to fix a memory-bound job

LeverWhat changesReal-world name
Faster carrierB goes upMore memory bandwidth (new hardware)
More math reusing the same bytesIntensity goes upBatching
Fewer bytes for the same mathIntensity goes upQuantization
Catch on batching: the extra work must reuse bytes you're already moving.
✗ Job A run twice separately: 40 FLOPs, 16 bytes. Intensity is still 2.5.
✓ Two requests sharing one read of the weights: 40 FLOPs, about 8 bytes. Intensity is about 5.

If a job is compute-bound, none of these help much. You need a faster calculator (more FLOP/s).

8Back to your model (Week 1 numbers)

Decode: memory-bound
Reads all the weights to make one token. Little math per byte, intensity around 1, far left of the ridge.
→ Flat at ~250 tok/s whatever the prompt length.
Prefill: moves toward compute-bound
Reads the weights once for every prompt token. Much more math per byte.
→ Got faster with longer prompts: 768 → 2,034 tok/s.

Your model is 4-bit (quantization lever) and serving systems batch users together (batching lever). Both raise intensity for decode.

9Check yourself

Same toy machine (10 FLOPs/sec, 2 bytes/sec). A job has 30 FLOPs and 10 bytes. Starved or swamped? How long does it take?
Answer Intensity = 30 ÷ 10 = 3, below the ridge of 5, so the calculator is starved (memory-bound). Time = max(30 ÷ 10, 10 ÷ 2) = max(3, 5) = 5 s.
Same machine. Double the bandwidth to 4 bytes/sec. How fast are Job A and Job B now?
Answer Job A: max(2, 8 ÷ 4 = 2) = 2 s, twice as fast. Job B: max(10, 2) = 10 s, unchanged. Speeding up the worker who isn't the bottleneck does nothing.
